# Abuse handling

Status: built (2026-10-08, #47). Anyone can sign up with an email address, create organizations and upload meeting attachments (PDF, DOC, DOCX, TXT, RTF, 10 MB each) that only the organization's members can see; public share links show bylaws text only, never files. The owner asked for protection against child sexual abuse material (CSAM) and pirated material. US law; a lawyer reviews the result before launch.

## Decisions

- **The Terms say what is prohibited and what happens.** A "Prohibited content" section names CSAM explicitly (reported to the National Center for Missing & Exploited Children as the law requires, and the account closed), content that infringes copyright or other rights, malware, and anything illegal; Robbie may remove content and suspend or close accounts that break the terms. "Copyright" gives the six elements of a DMCA notice (17 U.S.C. 512(c)(3)), the designated agent, the counter-notice process in two sentences, and the repeat-infringer policy. "Reporting a problem" gives the abuse address and asks reporters not to attach or forward the content. The Privacy Policy gets two lines: reports to NCMEC, and a year's retention of removed material where the law requires it. The plain voice and `LegalSection` structure stay.
- **Every contact value lives in `frontend-unified/src/pages/legal/legalContact.ts`**: `PROVIDER_NAME` (who provides Robbie, named in the opening of both pages; empty until the owner fills it in, and the pages say "the operator of Robbie"), `PRIVACY_EMAIL` (moved from `LegalPage.tsx`), `ABUSE_EMAIL` and `DMCA_AGENT` (name, postal address as lines, phone, `copyright@robbie.scouch.dev`). The Privacy Policy says removed material (copyright, malware, CSAM) is kept at least a year in a restricted folder, and longer when the law or law enforcement requires; governing law and liability are left to the lawyer. The agent's name, address and phone are empty until the owner registers the agent at dmca.copyright.gov; `DmcaAgentDetails` shows only what is filled in, so until then the Terms give the email alone and nothing that looks like an address.
- **`TERMS_VERSION` becomes `2026-10-08`.** Every user accepts again on their next request (the API and the socket answer `TERMS_NOT_ACCEPTED` until then). The demo seed, the integration helpers, mobile and e2e all use the constant, and the seed rewrites the demo people's acceptance on every run, so nothing else changes.
- **Suspension is a column, checked at the session finders.** `User.suspendedAt` (nullable; migration `suspend_users`, generated by Prisma). `findSession` and `findSessionById` return null for a suspended user, so `authenticate`, the socket handshake and a recovered socket all refuse without their own checks. Sign-in refuses quietly, so a refusal confirms nothing: a code request goes through the same steps (and the same per-email limit) but never sends the code. In its place it waits a random 150 to 700 milliseconds, about as long as a send to the provider takes, and answers 502 as a send would when sending is failing (production without a provider, or the provider's latest send failed). Verify answers as a wrong code does, after the usual code checks, the test code included.
- **The server closes sockets whose session ended elsewhere, every minute.** The operator's script runs in its own process (`docker compose exec`) and can't reach the server's sockets, and a socket checks its session only when it connects. `disconnectSocketsWithoutSession` (`socket/sessionSockets.ts`) runs on an unref'd 60-second interval beside the hourly cleanup: one query for the distinct session ids of the open sockets (live: not deleted, not expired, user not suspended), and the rest are disconnected. It also catches sessions that expire or are signed out from another process. A per-action check was the alternative; it costs a query on every meeting action for a case that happens almost never.
- **One operator script, `handleReport`** (`src/scripts/handleReport.ts`, logic in `src/abuse/reportHandling.ts` so it can be tested): `--attachment <id> --kind <csam|copyright|other> --note <text>`, `--restore <folder> --note <text>`, `--record-report <folder> ...`, `--suspend <email>`, `--unsuspend <email>`, each with `--dry-run`. `--kind` is required with `--attachment` and recorded in the manifest; `--note` is required with `--attachment` and `--restore` (the record of why), refused elsewhere. It never prints or opens contents; files are hashed and copied as bytes.
- **A restore for copyright counter-notices** (17 U.S.C. 512(g) has the provider replace the material). `--restore <folder>` recreates the attachment with its old id on the same agenda item or packet, and refuses with a clear message if that is gone; copies the file back into the uploads under a new name the server chooses; checks it against the manifest's SHA-256; and marks the manifest (`restoredAt`, `restoreNote`, `restoredStoragePath`), keeping the preserved copy. It refuses anything that may be CSAM: kind `csam`, a recorded CyberTipline report, a note that mentions CSAM, NCMEC or the CyberTipline, and a manifest without a kind. It doesn't count toward the storage limit's refusal (an operator's legal duty).
- **Preserve, verify, then remove.** `--attachment` refuses a linked document (no file), copies the file into its own folder under `PRESERVE_DIR` (`<time>-<id>/`, mode 700, the copy 600, never overwriting), checks the copy's SHA-256 against the original's, writes `manifest.json` (id, display name, file name, storage path, type, size, SHA-256, uploader and time, organization, packet with its code and title, agenda item, time preserved, the retention fields below, the note), then deletes the original file and, last, the row: a failure leaves a record, never a file without one. Run again, the command finds the earlier verified copy (a folder for the same id whose copy matches its manifest) and finishes the removal instead of copying again. Only ENOENT counts as a missing file (EACCES, ELOOP and the like stop it), a stored path that isn't a regular file is refused, and a missing file is refused unless `--missing-ok`, when the manifest says `fileMissing: true` with `sha256: null`. `PRESERVE_DIR` defaults to `preserved` beside the uploads directory (so `/data/preserved` in the image, where it is also set explicitly), and the script refuses a folder inside the uploads directory, which the backups cover.
- **The year runs from the CyberTipline report.** 18 U.S.C. 2258A(h) counts the year from the report's submission, which comes after the removal. So the first manifest has `keepAtLeastUntil` (a year after preserving), `keepUntil: null`, `reportedAt` and `reportId` null, and a `retention` sentence saying so. `--record-report <folder> --reported-at <date> --report-id <number>` records the submission and sets `keepUntil` a year after it, rewriting the manifest in one rename (a temporary file, then `rename`); a second run corrects it and prints what it replaced. A date in the future and a folder outside `PRESERVE_DIR` are refused. The runbook: preserve, report, record the report, then keep the folder until `keepUntil` or until law enforcement releases it, whichever is later.
- **Uploads record `uploadedBy`.** The column existed but the upload route never set it, so a manifest couldn't name the uploader. Files uploaded before this release show `null`.
- **The preserved volume is never backed up.** It is a named volume on the app only; the backup service doesn't mount it, so reported material never spreads into the nightly tarballs or the copies taken off the server. The runbook says to keep each folder a year (18 U.S.C. 2258A(h) as amended by the REPORT Act) and never to delete the volume. After a CSAM removal the runbook also has the operator take a fresh backup and delete the older uploads tarballs that held the file, on the server and off it: the preserved copy is the one the law requires, and other copies are only possession risk.
- **Each organization's files are capped**, `ORG_STORAGE_LIMIT_MB` (default 500) across its packets and agenda items, so one account can't fill the disk. The upload stores the file, then checks the sum and creates the row in one transaction under `pg_advisory_xact_lock(hashtext(organizationId))`, so two concurrent uploads can't both take the last of it; a refused upload's file is deleted and the answer is 413 "This organization has used its 500 MB of storage for files. Remove some files to add more." (the configured number). A bad value stops production at start-up and is a warning elsewhere. The web client now builds every upload error with the existing `failure` helper, which also survives a non-JSON body.
- **The runbook** (`docs/deploy.md`, "Handling a report") covers finding an attachment's id (the download link, or a read-only query of the records), the commands as `docker compose exec app node dist/scripts/handleReport.js ...` (the image's working directory is `/app/backend-node`), CSAM, copyright notices and counter-notices, a repeat-infringer rule (three notices that stood, sooner when flagrant), other abuse and law-enforcement requests. "Before launch" lists the mailboxes, the DMCA agent registration (renewed every three years) and filling `legalContact.ts`.

## Out of scope, known

- No in-app report button and no automated scanning (hash matching against known CSAM, such as PhotoDNA): reports come by email. Matching would need a vendor agreement and is worth revisiting if Robbie opens to the public at scale.
- Suspension has no reason column and no screen; the operator's own records hold the why.
- Robbie keeps no IP addresses, so an NCMEC report carries the account's email and the file's details only.

## Self-review

- Placeholders: the agent's name, address and phone are deliberately empty and the Terms render without them; the "Before launch" checklist and `legalContact.ts`'s comment say who fills them.
- Contradictions: the Terms say the account is closed for CSAM; the runbook suspends it and leaves it suspended, which is closing it without deleting the records the report needs.
- Ambiguity: "within the law's time frame" for NCMEC is "as soon as reasonably possible" (2258A(a)(1)); the runbook doesn't invent a deadline.
- Scope: everything here was asked for except `uploadedBy` on upload and the socket sweep, both needed for the asked-for behavior to work.

## Tests

- Unit: argument parsing (each action, `--kind`, `--missing-ok`, `--restore`, `--record-report` with its date and number, normalization, exactly one action, options with the wrong action, unknown options), the manifest (both parents, a 29 February, the retention fields), hashing, `printable`, the preservation root, the socket sweep, a recovered socket in no meeting, the storage limit's parsing and message, the start-up check, the legal pages (the sections, the provider, the addresses, the agent with and without its details, the restore wording, the retention line), the upload error in the API client and the packet builder.
- Integration: preserving (copy and hash, permissions, manifest, file then row removed, other files kept; a dry run; a missing file refused, then recorded with `--missing-ok`; EACCES stops it; a symbolic link refused; a failed file delete and a failed row delete each finished by a second run from the same folder), recording a report (the year from the report, the manifest replaced in one rename, a correction, a future date and a folder elsewhere refused), restoring (same id and place, a new name, the hash, the manifest marked, a member can download it; refused for kind csam, a CSAM note, a recorded report, no kind, a changed copy, a deleted agenda item), suspension (sessions ended, the old token and a later session refused by the API and the socket handshake, the code request sends nothing and takes a send's time, fails when sends fail, an earlier code and the test code refused, unsuspend restores sign-in), the session finders and `liveSessionIds`, and the storage limit (413 with the message and nothing left behind, refused before writing, two uploads at once near the limit, a failed record removing its file, only the organization's own files counted, `ORG_STORAGE_LIMIT_MB`, `uploadedBy`, a removed file freeing space).
